# Symphony

A lost worker transport acknowledgement does not require another execution when
the original owned process is proven stopped and a read-only native observation
proves the same exact turn completed. The controller reconciles that result through
ordinary adoption, preserving the original failure and stop evidence. Missing or
contradictory completion proof remains uncertain.

Pre-session resume conflicts use correlated typed evidence rather than requiring
the worker and controller to independently reconstruct an English error. Other
RPC failures and ambiguous starts remain protected from automatic source retries.

The Desktop broker preserves a serialized known result before publishing its
response. Publication and bookkeeping can resume after a process restart without
executing the operation again. Conflicting or invalid files fail closed; saved
results do not restore expired permissions or in-memory admission handles. This
does not claim durability across host power loss.

MR owner preparation initializes its read-only native actor before the short
remote/owner window. Finalization still checks the physical checkout and collects
fresh latest-turn, queue, and confirmation evidence after the owning Desktop read.
Reader lifetime never authorizes another model turn or restores a consumed handle.

Symphony turns project work into isolated, autonomous implementation runs, allowing teams to manage
work instead of supervising coding agents.

The local Jira factory keeps source-writing and exact-commit review in isolated
worktrees; contract-only conversations can stay in their repository Project
without allocating a worktree.
An experimental opt-in native reader can pin private local Codex and SQLite roots.
An optional pinned-origin workflow setting routes fresh ticket-supervisor specialists into
that storage; existing workers keep their recorded execution/recovery routes.
Its durable origin preserves directory identity across restart and exports provenance
only from the same initialized reader; it does not attest database contents.

Ticket-local manual-validation admission denials remain visible without blocking
unrelated queued or active work. Global configuration, provider, runtime and ledger
failures still fail the tick. A leased callback stops when its renewing owner dies;
the durable lease expires normally, and already-issued external effects remain
uncertain until exact readback reconciles them.

A default-off ticket-chat route reserves one projectless Desktop parent per
ticket and repository route, separately from delivery workers. Enabled startup
qualifies the configured runtime before factory children start; individual claims
and worker sessions retain their own fresh checks. This is not production rollout
approval, and the deployed route remains disabled; existing factory runs are unchanged.
Its local context/inbox layer now supports bounded evidence drilldown and staged,
read-backed commands; staging alone never starts work or changes Jira.
Controller updates display an immutable as-of snapshot; direct human commands
still refresh their binding before staging. Presentation ACKs are not delivery
or source-authorization evidence.
Specialist notices share one metadata shape across formatting and parent binding;
only an exact linked-run ledger notice and visible final readback authorize completion.
Explicit contract revisions and candidate rework can use a read-only native-input
payload preparer, avoiding model transcription while retaining exact completed-turn
and staging-receipt checks. Preparation is not acceptance or permission to work.
The disabled worker layer now reserves one checkout sequentially, binds each
result to its exact role/turn/candidate and owned-process receipt, and supports
same-invocation reconciliation. Required live validation and native shutdown
acceptance remain gates before dispatch integration or enablement.
Native SOURCE startup and retained SOURCE turns now fail before side effects
until containment is proved; read-only review and legacy transport are unchanged.
The disabled FILE_SOURCE adapter instead keeps the worker process read-only and
serves bounded repository reads, hash-checked edits and single-file deletion through controller-owned
tools. Durable edit intent supports readback after lost responses; this is not
native end-to-end acceptance or permission to dispatch real tickets.
Native FILE_SOURCE admission and retained turns are also fenced. Its controller
tools now use a hash-pinned, sandboxed descriptor-relative helper with physical
checkout identity checks. Unproven helper exits quarantine the edit rather than
permitting replay or release. Full shutdown/recovery and controller checks still
require acceptance before workers may use this route.
The disabled controller check catalog now supports one fixed tree-to-tree Git
whitespace check. Candidate-bound, owned-process receipts persist outside source
before reply; recovery reads the same invocation and unresolved checks retain
checkout ownership. This does not yet provide build/test or live-validation
execution, and does not enable native dispatch.
The next test-evidence route reuses authorized GitLab CI preflight rather than
provisioning a new local build environment. A pure CI binder now rejects stale
merge-result evidence unless its source parent is the exact candidate. It does
not fetch CI, attest connector provenance, or authorize a push or draft MR.
Current-pipeline identity is pinned to the MR's observed `head_pipeline`, not
merely a matching source SHA. Controller schema discovery uses an existing
idle MCP session, without waking a model or granting tool invocation access.
Schema 22 adds a fixed controller companion: mutating invocation bindings commit
before launch, child-exit evidence persists before reply, and recovery reads the
same claimed invocation without launching another writer. Controller callback
loss and an actual fixture controller-VM crash are tested offline. A proven
stopped edit can be cancelled only with unchanged source and no invocation
temporary; ownership remains reserved and only a new logical call can retry.
Attested orphan temporaries can now be reclaimed through a fixed helper after
the original writer's actual exit, while the same source reservation remains
held. Original and cleanup helper self-PIDs and durable receipts are checked;
replacement files and unproven ownership stay protected. Full crash/fault and
native acceptance remain unfinished.
Native checkout identity inspection now uses fixed, environment-isolated Git
under a read-only OS profile; configured filters cannot perform side effects.
Controller commit/push/fetch behavior is unchanged. This does not yet implement
the separate build/check or live-validation executors.

## Running Symphony

### Requirements

Symphony works best in codebases that have adopted
[harness engineering](https://openai.com/index/harness-engineering/). Symphony is the next step --
moving from managing coding agents to managing work that needs to get done.

### Option 1. Make your own

Tell your favorite coding agent to build Symphony in a programming language of your choice:

> Implement Symphony according to the following spec:
> https://github.com/openai/symphony/blob/main/SPEC.md

### Option 2. Use our experimental reference implementation

Check out [elixir/README.md](elixir/README.md) for instructions on how to set up your environment
and run the Elixir-based Symphony implementation. You can also ask your favorite coding agent to
help with the setup:

> Set up Symphony for my repository based on
> https://github.com/openai/symphony/blob/main/elixir/README.md

## Bounded factory CI repair

The native factory's CI-repair candidate is opt-in and disabled by default. It
separates immutable, exact-pipeline diagnosis from a once-only repair claim,
restricts the existing writer's file access before edits, and retains failed CI
and uncertain push history across descendant candidates. Only the controller may
commit, push, or reuse the recorded draft MR; a fresh successful pipeline for the
new SHA still precedes independent verification.

Controller-only Gazelle/gofmt generation passed its pinned-tool, runtime-confinement,
journaled byte-CAS and recovery acceptance gates. The local schema41 artifact is
deployed with native bounded repair enabled. A normal live tick has recorded the
diagnosis and claimed repair round1; repaired output and delivery are not implied
by admission. Product compilation and tests
remain in CI. See the implementation README for the local policy boundary.

## Shared factory instruction bundles

New ordinary native review admissions add structured criterion coverage and
prior-finding closure. Version 2 authors each finding once with a stable ID,
classification, required-repair or observation disposition, and a contract or
established safety basis. An initial review is comprehensive; repair follow-ups
bind closure, the exact changed-path delta, regressions, and any previously
unverified criteria. Carried PASS evidence retains its original provenance.
Optional observations do not block PASS or become writer obligations. New and
unresolved in-contract defects use the same bounded repair process.
The controller, not the reviewer, owns the normal limit of
two automatic repairs after the initial review, without earlier classification-based
stops. Genuine contract, environment, or human-decision blocks remain distinct.
Dashboard policy stops explain the rule independently
of factory health. Legacy admitted instructions and verdicts remain unchanged.
An explicitly approved, exact-verifier single-repair budget exception can resume
one stopped legacy `BLOCK` without changing global limits or resetting history.
The controller and successor physical publication codec both validate its scope.
Source writers return small operational results: CONTINUE, COMPLETE or BLOCKED,
changed paths, a controller commit message, blockers and honestly unrun checks.
Verifier feedback remains repair context, not a second acceptance protocol the
writer must satisfy. CONTINUE saves a coherent unfinished increment and resumes
the same writer; COMPLETE requests independent verification, never acceptance.
Retained writers still use their original admitted schema and immutable result
bytes, but acceptance-style coverage, classifications and closure rows in their
old reports are advisory. Ownership, settled tool I/O, checkout identity, parent
SHA, actual edit scope and exactly-once adoption remain enforced. Rejected unsafe
operational results require report recovery without discarding edits or rerunning
the source worker. Independent verifier PASS still requires all admitted criteria
and bound path checks to pass.
Core ticket admission and advancement are independent of parent presentation: attested route identity is
required, but a bootstrap acknowledgement or successful native history read is
not source authority. Unavailable readback is a communication warning. Durable
OPEN questions, staged PENDING commands, ACCEPTED commands awaiting application,
and active amendments hold ordinary progress. Accepted decisions apply before
work advances; uncollected raw text is not an immediate hold or cancellation.
Fresh checkout intents bind immutable parent payload/identity rather than changing
bootstrap presentation fields. Retained intents keep their original field sets
and bytes, including their original uncertainty fences.
Physical publication still uses its existing presentation fences. Fresh CI and
generation action snapshots also retain mutable parent/bootstrap observations;
removing those dependencies belongs to the subsequent effect-recovery work, not
this core-advancement change.
One explicit, deterministic report-only correction can reconcile duplicated v1
finding descriptions without changing original bytes, evidence, verdict, or repair
budget. An exact policy-stopped REPAIR can receive a separately journaled,
operator-authorized one-repair continuation; automatic attempts remain two used,
and another REPAIR stops again. Historical BLOCK authority remains distinct.
When legacy counters already exceed configured limits, that exact operator
receipt can explicitly bind one additional implementation iteration: configured
25/10, current 26/12, next 27/13. It does not reset counters or change WORKFLOW.
Honest CONTINUE advances to 27 and stops before another source iteration.
One exact, explicitly authorized read-only completion confirmation can finish an
adopted continuation at its implementation limit without reopening source edits,
granting another repair, or replacing CI and independent verification.

The prepared schema43 integration embeds complete role skills and shared review
criteria in restricted native packets, with immutable admission snapshots and
exact task/prompt links. It preserves independent verification and controller-only
Git/MR actions. Deployment and actual runtime packet readback remain separate
gates; the old shared `autopilot` compatibility copy stays until those pass. See
[the implementation contract](elixir/README.md#shared-role-instruction-admission).

Factory startup, ledger openings and updated local release tools refuse unsupported
native-history formats before mutation. This binary supports legacy unversioned
bindings/V1 completion receipts and explicitly bound V2 worker origins/receipts;
an optional pinned-storage selector applies only to fresh ticket-supervisor specialists.
Existing workers retain their recorded routes, while ticket masters and controller
operations stay unchanged. See
[the admission boundary](elixir/README.md#native-history-upgrade-admission).
